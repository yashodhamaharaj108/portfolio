Almost every system I work on has to accept a file from somewhere else and turn it into records. The shape of that pipeline is nearly always the same. What differs is where the design gives something up, and that part rarely makes it into a diagram.

So this diagram is about the trade-offs. Pick a stage to see what that choice costs.

## Why the trade-offs belong in the diagram

A box-and-arrow diagram shows what the system does. It almost never shows what the design gave up, which is the part worth discussing in a review. Writing the cost next to each stage forces the question early, while changing the answer is still cheap.

It also makes the diagram useful later. When someone asks six months on why imports are queued rather than immediate, the reason is next to the box instead of in somebody's memory.

## How this page is built

The diagram is a small Astro component with no framework behind it. It renders as a plain list of stages followed by all of the notes, and a short script upgrades that into something you can click through. If the script never runs, the page still says everything it needs to, and arrow keys move between stages once it does.

The source is in [the repository for this site](https://github.com/yashodhamaharaj108/portfolio), in `src/components/SystemMap.astro`.
